# 当前实现状态 · v0.1.2

## 本轮结果

- 针对真实钢琴与镲片素材中“极弱人声/贝斯残留被转录出音符”的问题，新增保守近静音检查：保留音频、跳过自动转录并给出说明。
- 判定同时要求整轨 RMS ≤ -75 dBFS、相对原音 RMS ≤ -40 dB、峰值 ≤ -45 dBFS、最响 100 ms RMS ≤ -60 dBFS；全零音频直接标记。短促打击声不会仅因整段平均电平低而被跳过。
- 新增可选 `Track.analysis`，记录有限的电平数值与处理标志；旧工程兼容，没有自动删除旧音符。细节见 [MODELS.md](MODELS.md)。
- 明确 4/6 轨是固定输出类别，不是乐器存在检测；四轨没有钢琴输出，镲片包含在鼓轨。
- 独立诊断后，已通过真实 API 与 worker 新建「001 旋律 · 六轨修正版」：钢琴转录 102 个预测音符，鼓保留音频，四条近静音轨跳过转录；4 个已有工程的 JSON 逐份比对完全未变。
- 本轮后端 44 项、前端 61 项、桌面配置 2 项测试通过，SDK 与前端 TypeScript 检查通过。生产构建通过；`Stem-Studio-0.1.2-x64.exe` 已生成并交付，107,988,135 字节。

## 本轮界面验证

已在同一前端的本机浏览器预览中检查真实修正版：默认选中钢琴，显示 2 条有信号 / 4 条近乎静音；上方音频模式只显示波形，MIDI 模式只显示音符，下方卷帘可编辑。人声独奏明确提示近乎静音，退出全部独奏后恢复未修改状态。六轨纵向滚动时左右音轨保持对齐。测试过程没有保存改动到工程。

流式任务逐条产出时，自动选轨会跟随有效音符轨；用户主动选中的轨道会保留。实际 Windows 扬声器输出与最终便携包全部原生交互仍需人工验收。

## 本轮独立真实样本诊断

用户的两份 `001 旋律` 上传文件相同，均为 25.34 秒；用户说明只含钢琴和镲片。只读检查原工程后，在独立副本上运行 `htdemucs_6s / auto`，未覆盖用户工程。

| 检查 | 结果 |
| --- | --- |
| 旧四轨主要信号 | 其他轨 RMS -32.79 dBFS，约 98.69% 原音能量；四轨没有独立钢琴输出 |
| 旧四轨残留误报 | 人声/贝斯分别约 -91.34/-91.55 dBFS，旧版本仍转录出 43/34 个音符 |
| 独立六轨结果 | 18.04 秒完成；钢琴约 95.99% 原音能量，鼓约 1.35%，其余输出均为极弱信号 |
| 短促打击声 | 位于约 0.3、1.5、2.7、3.9 秒；鼓轨峰值约 -14.99 dBFS，不能当作整段无效轨删除 |
| 钢琴独立转录 | 真实 Basic Pitch 约 4.16 秒，99 个预测音符，Type 1 MIDI 导出、回读成功；未逐音人工校对 |

RMS 和能量比例用于描述信号，不是乐器分类置信度或识别准确率。六轨在这份素材上比四轨更适合独立钢琴输出，不保证所有歌曲都有相同效果。原始证据在工作区 `work/user-audio-diagnosis/`，测量方法与边界见 [MODELS.md](MODELS.md)。

## 历史启动环境问题的结论

此前从 `CodexSandboxOffline` 受限上下文启动时，GPU 子进程出现 `0xC0000135`，renderer 出现 `launch-failed / 49`；原版 Electron 最小页面也复现。检查范围内没有发现实际缺失的直接 DLL 依赖。

[Chromium 错误码定义](https://chromium.googlesource.com/chromium/src.git/+/refs/heads/master/sandbox/win/src/sandbox_types.h) 将 49 定义为无法创建受限令牌。后续在正常桌面用户 Lucas 下，最小页面达到 renderer-loaded，新版未封装应用也执行了生产 React/Tone 界面，没有 renderer/preload 错误，并保持 Electron 沙箱开启。这支持此前失败来自启动环境，而不是 React 界面代码；没有通过关闭沙箱或降低应用安全设置规避。

## 功能范围与产物

- 鼓与镲片音频可试听，不识别鼓音符；四轨没有钢琴输出，其他轨可能混合乐器；输出名称不代表检测到该乐器。BPM 未自动检测，拍号固定 4/4。
- 当前是本机单用户应用，不包含公网认证、多人协作、配额和计费。
- 当前交付包：`Stem-Studio-0.1.2-x64.exe`，旁置有效的 `recognition.local.json`。
- 模型验证记录：`examples/basic-pitch-smoke.json`、`examples/basic-pitch-smoke.mid`；四轨工作区原始证据在 `work/smoke-demucs/`。
- MP3/FLAC 格式验证记录：`examples/codec-smoke.json`。
- 接口合同：`docs/openapi.json`。
- 模型环境兼容约束：resampy 依赖 pkg_resources，固定 `setuptools>=75,<81`，已用 80.10.2 验证。

## v0.1.3 功能与验证（继续保留）

- 后台服务优先使用 Windows `pythonw.exe`；回退启动也隐藏窗口，取消可能创建控制台的 Windows detached 设置。日志写文件。
- 服务启动增加跨实例锁与启动进程记录，避免模型进程首次心跳之前被重复启动。已清理旧测试实例和重复的模型进程，保留用户打开的编辑器；API 和 worker 已用无控制台进程运行。
- 取消任务时回收该任务的整棵模型子进程树，并等待退出，避免只结束 Python 启动器而留下实际推理进程和日志占用。
- 新增钢琴专用模型 `piano_highres`。六轨分离后只对钢琴使用专用模型，或对已知单钢琴原音直接转录；其他音高轨仍使用 Basic Pitch。没有静默回退，也没有通过删除短音符或节拍量化制造整齐结果。
- 新增用户主动启用的镲片击打点提取 `cymbal_onsets`。保留分离音频，音符进入 GM 鼓通道；可修改击打点、力度和试听音色，支持撤销。默认 GM 49 是用户可修改的音色映射，不是自动分类出的镲片种类。
- 相邻同音高鼓点保留每次击打，不再按旋律延音合并。MIDI 试听增加简单噪声合成的鼓音。
- `Track.transcriptionEngine` 记录实际引擎；旧数据未记录时明确说明，近静音跳过轨单独提示。原有工程不自动重算。

## 真实素材结果

通过真实上传接口、队列与模型重新建立 **001 旋律 · 钢琴专用与镲片**，ID `7460312564f441b09e8c11bd829698e2`，时长 25.3398 秒，状态 `ready`。原来的 6 个工程逐份 JSON 比对完全未变。

| 检查 | 结果 |
| --- | --- |
| 钢琴 | `piano_highres`，67 个预测音符；2 个短于 300 ms；时长中位数 1.212 秒 |
| 镲片 | 4 个击打点，约 0.379、1.576、2.779、3.976 秒；默认 GM 49 |
| 人声、贝斯、其他、吉他 | 近静音检查跳过自动转录，各 0 音符，音频仍保留 |
| 分轨音频 | 6 个真实 WAV 均能读取 |
| MIDI | 导出并回读 71 个 note-on，其中 4 个在 MIDI 第 10 通道（代码 channel=9）；时间误差小于 2 ms |
| 历史工程保护 | 6 个原工程均未改动 |

工作区证据：`work/piano-cymbal-validation/result.json`。交付 MIDI 为 `001-旋律-钢琴专用与镲片.mid`。

**准确率边界：** 同一旧钢琴 WAV 上，Basic Pitch 的 102 个预测音符与专用模型的 67 个预测音符已有独立对比。没有逐音人工标注的标准答案，音符更少、更长不等于准确率已证实提高，仍可能漏音或延音过长。小块也可能是真实短音或重新击键。当前工程不存储模型预测的踏板 CC64。完整模型信息见 [MODELS.md](MODELS.md)。

镲片检测适合用户确认打击乐为镲片的素材，不区分完整鼓组。密集重叠、非常弱的击打、分离串音可能造成漏检或误检，不能将它称为通用鼓谱识别。

## 历史：v0.1.4 使用与交付

v0.1.4 当时使用 `Stem-Studio-0.1.4-x64.exe` 或配套「连接本机识别服务.cmd」。切换该版本前需要保存编辑并关闭旧窗口，已有识别工程保留；当时的新结果位于项目列表的「001 旋律 · 钢琴专用与镲片」。

该旧版的 Python、模型环境及权重由旁置 `recognition.local.json` 引用，没有打进 EXE，换机器需要手动配置。0.2.0 已改为安装向导与自动准备环境，当前流程见 [桌面说明](DESKTOP.md)。源码 ZIP 不包含用户音频、工程数据库、模型缓存或本机绝对路径配置。

四轨/六轨仍是固定输出类别，不代表检测出对应数量的乐器；“其他”仍为混合轨。BPM 是用户设置或默认值，修改只影响网格，不改变音符秒数或原音速度。应用面向本机单用户，不包含公网认证、收费或协作。

# Figma 前端设计与代码生成说明

本文可直接粘贴给 Figma 的设计或代码生成功能。目标是生成可交接的 React 前端，真实后端与模型由另一侧实现。当前交付不包含已经完成的前端界面。

---

## 可直接使用的提示词

请为一个中文「多轨音乐工作台」设计并生成前端。它的工作流是：上传音乐 → 后端分离音轨 → 各轨识别音符 → 在钢琴卷帘中编辑 → 保存工程、导出 MIDI。产品暂名「分轨工作台」，不要复制其他网站的品牌、图标或页面素材。

### 1. 工程与交付要求

- 使用 React、TypeScript、Vite、Tailwind CSS、shadcn/ui。
- 路由固定为 `/projects`、`/upload`、`/projects/:id`。访问根路径可跳转到 `/projects`。
- TanStack Query 管理项目、任务和服务端状态；Zustand 管理编辑器选择、草稿、撤销重做、播放状态。
- 波形组件为 WaveSurfer.js 预留适配层；音频播放为 Tone.js / Web Audio 预留统一时钟适配层；大量音符使用 Canvas，避免每个音符都变成一个复杂 DOM 节点。
- 将页面、领域组件、API 适配、演示数据分开。接口代码集中在 `services/`，优先接入随项目提供的 TypeScript SDK，不要把请求散落在组件中。
- 真实接口路径、上传字段、SSE 事件格式以配套 API 文档和 FastAPI OpenAPI 为准。不要自行编造接口，也不要在前端写入私密密钥。
- 在尚未接入真实 API 时使用显式的演示模式。页面顶部持续显示「演示数据 · 未连接识别服务」，项目卡片也显示「演示」。演示状态由可见的开发演示控件切换，不使用计时器假装真实模型正在完成任务。
- 输出完整可运行的前端源代码、安装和启动说明、页面路由说明、接口接入位置说明。组件应能复用，不要把整个应用写在一个文件里。

### 2. 视觉方向

这是长期使用的音乐编辑工具。默认使用浅色工作区：接近白色的背景、低饱和灰色面板、清晰的文字层级，以蓝紫色作为主操作颜色。编辑器可提供深色主题，但两种主题的对比度都要足够。不要做营销首页、巨大宣传区或大量装饰动画。

界面语言为简体中文。数字、时间和音高采用等宽字体。项目标题、操作按钮和错误提示使用易读的中文无衬线字体。间距统一使用 4 / 8 / 12 / 16 / 24 / 32 px。圆角控制在 8–12 px，分区主要靠边线与背景区分。

给每种音轨固定颜色，并同时显示名称和图标，不能只靠颜色识别：人声、鼓、贝斯、其他、钢琴、吉他、弦乐。首版默认四轨是人声、鼓、贝斯、其他；「其他」可能仍混有多种乐器，不能显示成独立钢琴或弦乐。钢琴、吉他、弦乐仅在数据实际包含这些轨道时出现。

### 3. 必须遵守的能力边界

1. 首版支持 `demucs_basic_pitch`（先分离再转录）与 `transcribe_only`（直接转录单乐器音频）两种模式。
2. 默认分离为人声、鼓、贝斯、其他四轨。不要把七种 Track.kind 类型理解成已具备七轨分离能力。
3. 首版鼓轨保留音频，可静音、独奏、调节音量和声像；没有鼓音符识别。明确显示「鼓音频可试听 · 暂不支持鼓音符转录」。不要画出假的鼓音符。
4. 「其他」是混合乐器音轨，显示「可能包含多种乐器，音符结果需检查」。不要承诺完整准确的总谱。
5. BPM 来自用户输入或默认值。默认可为 120，但必须标注「默认值，未自动检测」。用户在本次页面内修改后可显示「手动设置」。刷新后若 API 没有来源字段，统一显示「工程 BPM · 非自动识别」，不要凭数值猜来源。
6. 拍号首版为 4/4。显示为只读信息，不提供没有实现的变拍号选项。
7. 修改 BPM 默认只改变节拍网格和 MIDI 时间映射，保持音符的秒数位置不变。不要让它看起来像原音频自动变速。
8. 本轮没有和弦分析、歌词识别、自动编曲、智能补全、打印乐谱、变速跟随、GPU 云部署或账号付费功能。不要生成可点击但不工作的入口。

### 4. 数据模型

严格使用下列字段；不要把显示标签直接写入枚举。所有日期来自服务器，所有音符时间使用秒。

```ts
type ProjectStatus = 'empty' | 'queued' | 'processing' | 'ready' | 'failed' | 'cancelled';
type TrackKind = 'vocal' | 'drums' | 'bass' | 'other' | 'piano' | 'guitar' | 'strings';
type TranscriptionStatus = 'completed' | 'unsupported' | 'failed';

interface Note {
  id: string;
  pitch: number;           // MIDI 音高整数，0..127
  startSeconds: number;    // >= 0
  durationSeconds: number;// > 0
  velocity: number;        // MIDI 力度整数，1..127
}

interface Track {
  id: string;
  name: string;
  kind: TrackKind;
  program: number;         // GM 音色编号，0..127
  isDrum: boolean;
  muted: boolean;
  solo: boolean;
  volume: number;          // 0..1
  pan: number;             // -1..1
  audioUrl?: string;
  transcriptionStatus: TranscriptionStatus;
  notes: Note[];
  warnings: string[];
}

interface Project {
  id: string;
  title: string;
  status: ProjectStatus;
  bpm: number;
  timeSignature: '4/4';
  durationSeconds: number;
  revision: number;
  latestJobId: string | null; // 刷新后重新获取最近任务与进度
  createdAt: string;
  updatedAt: string;
  sourceAudioUrl?: string;
  tracks: Track[];
  warnings: string[];
}

interface Job {
  id: string;
  projectId: string;
  status: 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelled';
  stage: 'queued' | 'decode' | 'separate' | 'transcribe' | 'merge' | 'done' | 'failed' | 'cancelled';
  progress: number | null; // 0..1；null 表示服务端没有可靠百分比
  message: string;
  error?: string;
  createdAt: string;
  updatedAt: string;
}
```

演示标签可以保存在演示数据提供器的外层元信息中，不要随意给服务端 Project 添加字段。演示工程中可使用人工生成的音符和波形，但必须说明来源为演示。

### 5. 页面一：项目列表 `/projects`

**布局**

- 顶栏：产品名、当前「本机工作区」标签、主题切换。
- 标题区：「项目」与「上传音频」主按钮。
- 工具区：按名称搜索、状态筛选（全部 / 处理中 / 已就绪 / 失败 / 已取消），最近更新排序。
- 内容区：桌面使用卡片网格，也可切换紧凑列表。卡片包含标题、状态、时长、轨道数、更新时间；演示项目带明确徽标。
- 卡片主操作为「打开」。尚在处理的项目显示「查看进度」；失败或取消后有已完成轨道时显示「查看部分结果」。重新识别必须通过「新建项目并重新上传」，不能覆盖已有结果。
- 不要生成没有后端支持的删除、复制、云分享或协作入口。

**状态**

| 场景 | 显示与操作 |
| --- | --- |
| 首次加载 | 卡片骨架屏，不显示虚构工程 |
| 没有项目 | 简单空态、说明上传后可获得分轨与 MIDI、上传按钮 |
| 搜索无结果 | 保留搜索词，提供「清除筛选」 |
| 请求失败 | 显示失败说明和「重新加载」，保留上次成功加载的内容并标记可能过期 |
| 本地服务未启动 | 显示「无法连接本机服务」和重试入口；不要伪装成空列表 |
| empty | 「等待上传」 |
| queued | 「排队中」，不捏造队列位置 |
| processing | 显示当前阶段，只有存在可靠 progress 时才显示百分比 |
| ready | 「可编辑」，有 warnings 时显示提示数量 |
| failed / cancelled | 「处理失败」或「已取消」；如有保留轨道，明确标记「部分结果」，允许查看已有内容，不将它显示为整项识别成功 |

### 6. 页面二：上传 `/upload`

**布局与字段**

- 顶部返回项目列表，标题「上传音频」。
- 中间为拖放文件区与文件选择按钮，展示支持格式和大小限制。限制从 SDK/API 配置读取；未确定前不要随意写死宣传数字。
- 选择后显示文件名、大小、可读取到的时长、替换文件按钮。客户端读不到时长时写「上传后读取」，不要填 0 秒。
- 工程名称默认来自文件名，用户可修改，必填。
- 处理模式使用两张清晰的单选卡：
  - 「分轨并识别」：适合包含多种声音的歌曲；生成四类音频并转录有音高轨道。
  - 「直接识别音符」：适合已分离音轨、独奏或单乐器录音；跳过音源分离。
- BPM 输入框，默认 120，并持续说明「默认值，未自动检测；稍后可修改」。拍号显示 4/4。
- 主要按钮「上传并开始」。上传过程中防重复点击；同一个文件不会因为连点而创建多个任务。

**上传与处理状态**

- 本地校验错误显示在文件区或具体字段旁：未选择文件、名称为空、格式不支持、文件过大、BPM 无效。错误条件以实际后端合同为准。
- 如果上传实现提供真实字节进度，显示已上传字节与百分比；没有字节进度时显示「正在上传…」。禁止用随机数或时间估算伪造进度。
- 上传成功并得到项目/任务 ID 后进入该项目编辑器，展示处理面板。浏览器刷新时先获取 Project，再通过 latestJobId 获取最近 Job 并恢复事件监听；latestJobId 为 null 表示该工程还没有任务。
- 处理失败的提示区别于网络上传失败；只有重新上传文件的动作才叫「重新上传」。重新识别创建新工程，原工程及已完成的轨道保留。
- 任务取消要区分「正在请求取消」与服务器已确认的「已取消」。取消按钮不意味着 GPU 计算会瞬间停止。
- 长任务中断连线时显示「连接中断，正在重新连接」，不要立刻宣告任务失败；重新连接后读取服务器最新状态。

### 7. 页面三：编辑器 `/projects/:id`

**桌面布局**

1. 顶栏：返回项目、可编辑标题、项目状态、保存状态、保存按钮、导出 MIDI。
2. 播放工具栏：播放/暂停、回到起点、当前时间/总时长、播放来源选择、BPM、只读拍号 4/4、缩放与吸附选项。
3. 左侧轨道面板：每条轨道的名称、颜色、类型、转录状态、静音、独奏、音量、声像；当前选中轨道清晰高亮。
4. 中间主区域：顶部统一时间标尺与波形总览，下面为钢琴卷帘。左侧钢琴键固定，水平滚动控制时间，垂直滚动控制音高。当前轨道可编辑，其他轨道仅作为可选淡色参考层。
5. 右侧检查器：无选择时显示项目提示；单个音符选择时显示音高、开始秒数、持续秒数、力度；多选时显示数量并支持修改共同属性。
6. 底部状态区：音轨/音符数量、后台任务阶段、警告摘要、播放资源加载状态。

**正在处理时**

显示真实阶段：等待处理 → 解码 → 分离音轨 → 识别音符 → 合并工程 → 完成。直接识别模式跳过分离阶段。使用后端 message 作为补充说明，不声称正在运行某个未经后端确认的模型。

progress 为 null 时显示不确定进度动画与阶段文字；progress 有值时显示百分比。进度不需要每秒递增，也不能因为停留较久而自动加到 99%。只有服务器终态成功才显示完成。

后端会在发布 `track.ready` 事件前，将完整的单轨结果和对应音频资源映射原子写入工程。收到该事件后刷新 Project，显示真实已完成轨道，并允许试听其已存在的 audioUrl；不要把未发布的模型输出画成完成轨道。刷新页面也能重新获取这些部分结果。

排队或运行期间先禁用音符编辑和导出，并说明「任务结束后可编辑」。任务失败或取消后保留已完成轨道：显示失败/取消原因和「部分结果」提示，有保留轨道时可查看、试听、编辑和导出已保留内容，不能把任务状态改画为全部成功。重新识别需新建工程并上传，避免覆盖部分结果。

**音轨交互**

- 点击轨道选择它；音量和声像可以拖动，也提供键盘操作与数值提示。
- 存在独奏轨时，只播放未静音的独奏轨；没有独奏轨时，播放所有未静音轨。静音优先于独奏。
- `unsupported` 显示「暂不支持音符转录」，`failed` 显示「音符识别失败」。两者都不等同于音频不存在；audioUrl 有效时仍可听音频。
- `completed` 且 notes 为空时显示「未识别到音符」，不要画占位音符，不要归类为未知错误。
- `audioUrl` 缺失时显示「无分轨音频」。资源加载失败时可重试该资源，不能把整个项目变成识别失败。
- `strings`、`piano`、`guitar` 仅按真实数据呈现；默认四轨演示中不要出现假弦乐分轨。

**音符编辑**

- 双击空白区域新增音符；单击选择；框选多选；Shift 点击增减选择。
- 拖动音符主体改变开始时间与音高，拖动右边缘改变持续时间。开始时间不能小于 0，持续时间必须大于 0，音高与力度保持合法整数。
- 支持 Delete/Backspace 删除、撤销、重做。每次连续拖动只记为一次撤销动作。
- 钢琴键和音符悬浮提示显示音名及 MIDI 音高；编辑器采用的中央 C 命名规则全局一致，并提供 MIDI 数字以避免八度命名歧义。
- 吸附选项为关闭 / 1/4 / 1/8 / 1/16 拍值网格；改变吸附只影响后续手势，不能悄悄量化已有音符。
- 横向缩放保留鼠标所在时间位置，轨道波形、时间标尺、音符层和播放光标保持对齐。
- 超出原音频结尾的新音符可以扩展编辑视图；播放总长度取原音频时长与音符结束时间的较大值，原音频结束后不循环填充声音。

**播放模式与统一时钟**

- 明确区分「原音频」「分轨音频」「MIDI 音符」三种试听来源。
- 原音频模式播放原始混音，轨道静音/独奏/音量不改变原始混音；这些控件置为不可用并给出原因。
- 分轨模式可以听分离音频，音符修改不会改变这些录音；MIDI 模式播放编辑后的音符，首版鼓没有音符时不会凭空发声。
- 切换模式时保留播放位置。资源尚未加载时暂停并显示状态，加载完成后由用户决定播放。
- 波形是显示组件，所有音轨由一个音频时钟调度；不要给每个 WaveSurfer 实例独立按播放按钮。
- 点击时间标尺跳转；暂停后再次播放从当前位置继续；结束时停止并显示结尾位置。
- 首次播放遵循浏览器的用户手势要求；音频尚未解锁时显示可点击「启用试听」。未加载音源或浏览器拒绝播放时提供清楚的提示。
- 音符修改之后的 MIDI 试听与导出结果要一致。完整同步试听尚未接入时，按钮必须明确不可用，不能用 CSS 光标冒充已经发声。

**保存与冲突**

- 显示「已保存」「有未保存修改」「正在保存」「保存失败」。提供显式保存与 Ctrl/Cmd+S；不要浏览器弹出网页另存为。
- 保存携带当前 revision。服务器有更新时显示冲突面板，保留当前本地草稿，不要自动覆盖另一版本，也不要自动清空用户改动。
- 冲突面板至少支持「保留本地草稿并查看服务器版本」与「确认后重新加载服务器版本」。三方合并未实现时不要提供看起来可用的自动合并按钮。
- 有未保存修改时离开编辑器，提供「保存后离开 / 放弃修改 / 留在此页」；保存失败不能直接跳转。
- MIDI 导出应对应当前草稿：存在未保存修改时先保存，保存成功后导出；失败则提示并保留草稿，不能静默导出旧版本。
- 同一轨道、同一音高的重叠音符在 MIDI 导出时合并重叠区间，避免 note-off 截断仍在持续的同音；编辑器原始音符不被自动修改。若存在这种情况，在导出说明中提示，MIDI 试听层采用与导出一致的规范化规则；不同音高的复音不会因此合并。

### 9. 响应式与可访问性

- ≥1280 px：轨道面板约 240 px，检查器约 260 px，中间编辑区伸缩；保存与播放主按钮始终可见。
- 768–1279 px：轨道面板约 200 px，检查器改为右侧抽屉，工具栏可以折行，但时间轴与音符区不能错位。
- <768 px：项目列表单列，上传表单单列，编辑器主视图以试听与浏览为主；轨道与检查器使用底部抽屉。保留横向滚动与基本选择，不强迫精密音符拖动在狭小手机屏幕完成。
- 所有图标按钮提供中文可访问名称；焦点轮廓明显；控件可用键盘操作；重要状态配文字，不只用颜色。
- 播放进度不要每一帧通过读屏播报。任务阶段变化、保存成功与失败使用适度的状态播报。
- 输入框正在编辑、对话框打开或输入法正在组合文字时，不触发音符删除和空格播放快捷键。
- 尊重减少动画偏好。音频进度需要同步显示，但装饰性动效可关闭。

### 10. 必须能展示的完整状态集合

请提供一个开发环境专用状态切换器，使评审可以直接看到：

1. 项目列表加载、空、正常、有警告、筛选无结果、服务断开。
2. 上传未选文件、已选文件、非法格式、超限、上传中、上传失败。
3. 排队、解码、分离、转录、合并、完成、失败、取消请求中、已取消、SSE 重连中。
4. 编辑器读取中、不存在项目、逐轨结果已到达、就绪、就绪但有警告、鼓未支持、某轨转录失败、没有识别到音符、失败或取消后仍有部分结果。
5. 音频加载中、播放可用、音频加载失败、MIDI 音源不可用。
6. 未保存、保存中、保存成功、保存失败、版本冲突、离开确认。
7. 选中一个音符、多选音符、没有选中音符、所有轨道静音、一个轨道独奏。

该切换器只展示界面状态，必须带「界面状态演示」标签，在连接真实服务时默认隐藏。

### 11. 交付验收

- 三条路由完整，刷新详情页能恢复对应页面，不依赖从首页进入。
- 没有假装已调用模型的演示进度，也没有未实现能力的可用按钮。
- notes 使用秒，轨道种类与状态严格对应上述合同。
